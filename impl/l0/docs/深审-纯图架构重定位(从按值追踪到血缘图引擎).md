> 评议对象:把现行实现从 **按值追踪(Map<值, passport> 中心)** 重新定位为 **运行时血缘图引擎(显式节点 + 显式边的图,值不再是反查索引)**。

## 1. 现行架构(按值追踪)的真问题——确认命题成立

先确认提议要解决的痛点是否真实存在(避免伪命题):

### 1.1 byVal 兜底碰撞

`stamp-origin.js:240-253` 把每个字段值塞进 `globalThis.__wdpp_byVal[v] = fieldMap`。两个 API 都返回 `{name: "John"}` 时,`byVal["John"]` 被后者覆盖,前者丢失。**这是按"值"反查的固有过近似**,不是实现 bug。

### 1.2 深拷贝断身份

`lodash.cloneDeep` / `structuredClone` / `JSON.parse(JSON.stringify(x))` 产出全新对象,`WeakMap<obj, 子树并集>` 全部断,`__wdpp_fields`(可枚举 false 属性)被拷贝或丢失,只剩 `byVal` 兜底。

现行用 `__passthrough`(`babel-runtime.js:37-66`)在深拷贝调用边界递归复制 SM + `__wdpp_fields` + objectIndex —— 但**这是按 case 白名单**(cloneDeep / structuredClone / JSON.parse(JSON.stringify())),自定义深拷贝未识别仍断。

### 1.3 低熵值失效

`value-index.js:30-36` `LOW_ENTROPY` 黑名单跳 true/false/0/1/""/null/`'0'`/`'1'`/`'true'`/`'false'`。`status: 0` 这种合法业务字段永远没标,**只能走块级(props 整对象带照)**降级。

### 1.4 库内变换墙

antd `valueEnum`、dayjs `.format('YYYY-MM-DD')`、lodash `_.merge` —— 库内部未插桩,值进库时即使带标,出库时**已强转丢标**。现行靠"块级(props 带照对象)归到外层 host"(`component-bind.js:53-71`)兜底,**这是过近似,不是字段级**。

### 1.5 小结:三类根因都是"按值"的产物

| 痛点 | 根因 | 按值架构能修? |
|---|---|---|
| byVal 碰撞 | 值反查不区分并发 | ❌ 值同源不可区分 |
| 深拷贝断身份 | WeakMap 按对象身份断 | ⚠️ pass-through 白名单 only |
| 低熵失效 | 值无信息量 | ❌ 信息论上限 |
| 库内变换墙 | 库未插桩丢标 | ⚠️ 块级过近似兜底 |

**结论**:这四类根因**全部由"按值"或"按对象身份"两个抽象选择导致**,升级抽象是必要的。

## 2. "纯图架构/血缘图引擎"的三种解读 + 是否命中痛点

"纯图"和"血缘图引擎"在不同语境下指不同东西。逐一还原并评估:

### 解读 A:**运行时操作级 taint graph**(提议的"血缘图引擎"最自然的所指)

> 把每个赋值、运算、调用都建模为图节点/边。值只是图节点的属性。查询:DOM 节点 -> 反向 BFS 到 API 节点。

**形态**:
- 节点类型: `ApiSource` / `Operation(add, format, merge, ...)` / `FieldRef` / `DomNode`
- 边类型: `produces` / `derived-from` / `writes-to` / `conditional-by`
- 每条边带 `t = timestamp`,可重放
- 查询:`lookup(domNode)` = 反向 BFS 收集祖先 `ApiSource` 集

**对痛点的回答**:

| 痛点 | 运行时 taint graph 能修? |
|---|---|
| byVal 碰撞 | ✅ 不再按值查,按边查 |
| 深拷贝断身份 | ✅ Operation 节点记录 `cloneDeep(input)` -> output 的边,identity 沿边 |
| 低熵失效 | ✅ 操作级不是值级,`status = 0` 也是 `Operation` 节点的输出 |
| 库内变换墙 | ❌ **仍要插桩库**(Jalangi/NodeProf 方式),不插桩则图断 |

**库内墙**:这是 runtime taint graph 的根本问题。库内部未插桩 = 库内产生 `Operation` 节点的边缺失 = 图断。**唯一解 = 全量插桩 = DESIGN.md §14 否决的 Jalangi 路径**。

### 解读 B:**运行时"图作为查询模型"**(值仍盖戳,但存储/查询改图)

> 值仍盖戳(护照仍是值上的位图),但存储从 `Map<fieldId, Set<edge>>` 改为通用图数据库式存储;查询走图遍历而不是值反查。

**形态**:
- 节点 = fieldId / domNode / control stack frame
- 边 = data / control / conditional
- 值仍用 `Map<值, passport>`,查询从值开始走图

**对痛点的回答**: ❌ **完全没解决任何一类根因**。byVal 仍碰撞、深拷贝仍断身份、低熵仍失效、库内墙仍在。**只是把 §4 的图存储升级了**——这是优化查询效率,不是解决根问题。**提议若指这个,价值低**。

### 解读 C:**静态图(DESIGN-STATIC.md 已存在)**

> build-time 用 ts-morph 做抽象解释,产出静态图。运行时归因零开销。粒度止于"组件级 / 列表项 API 级",不做记录级 / cell did。

**形态**:见 `DESIGN-STATIC.md` §2-3。~16 条语言级规则覆盖所有 JS 构造。

**对痛点的回答**:

| 痛点 | 静态图能修? |
|---|---|
| byVal 碰撞 | ✅ 没运行时就无 byVal |
| 深拷贝断身份 | ⚠️ 静态可达(规则 5 库调用 union;§3.6 有界扫描),但合并输入并集,不是字段级 |
| 低熵失效 | ✅ 字段是 src 节点,值不重要 |
| 库内变换墙 | ✅ **天然免疫**——prop 源追踪即可,无需插桩 |

**判定**:静态图**真的命中所有根因,且成本最低**(零运行时归因)。但它**改变了命题**:从"运行时确认 did"变成"build-time 推 could"。

**关键洞察**:**静态图才是"纯图架构"的正确归宿**,但**不是这次提议的目标**。提议说"血缘图引擎"+"运行时"(否则不需要"引擎"二字)——这是解读 A,即 Jalangi 风格 taint graph。

## 3. 运行时 taint graph(解读 A)深审——为什么不可行

按 DESIGN.md §1 第一性原理 + §11 性能 + §14 否决方案三轴审查。

### 3.1 §1.1 两端可观测 vs 操作级全插桩

DESIGN.md §1.1:数据必经网络层 + DOM 写入点。所以**两端 + 拦截**是最小爆炸半径。

**操作级 taint graph 必须插桩所有运算**(赋值、加法、调用)——因为数据在运算中传递。每条 `a + b`、每个 `arr.map(fn)` 都得是图边。**爆炸半径 = 全部 app 代码 + 全部库代码**(不插桩库则图断)。

**违反 §1.4 opt-in**:不是"不碰 API 数据的代码行为不变",而是"碰了 API 数据的所有代码被插桩"。库内部运算被插桩 = 库自身变慢 = DESIGN.md §11.6 "千行表格 2-10x 慢"那个场景**默认发生**(库被插桩)。

### 3.2 §1.2 追踪 identity 不追踪 value —— "图"能坚持吗?

**部分坚持**:运行时 taint graph 节点是 `Operation`,边是 `derived-from`,**identity 沿边传播**——这是 identity,不是 value。byVal 没了,深拷贝断了也能补。✅

**但 identity 仍要"挂"在某物上**:操作级 taint graph 仍要把 taint 标在某物上(否则查询不到 DOM 节点)。通常是 taint 标在**运行时值**上(Operand)或**节点**(Node)上:

- 标在 Operand(值)上 → 退化为"带标值"(LabeledBox),回 DESIGN.md §5 Proxy 路线。**图只是值的载体,本质是值标**。
- 标在 Node(操作节点)上 → 操作节点有 taint = 操作节点的输入 taint。但 **DOM 节点是物理节点**,要"挂"到 DOM 上仍要靠值(`textContent = taint(opX)` 中的 `taint(opX)` 必须能查)——**绕不开值通道**。

**判定**:运行时 taint graph 没法彻底摆脱"值"。只能把值标变成"图边端点的属性",**形式上换存储,本质还是值标**。byVal / 深拷贝 / 低熵三类根因,低熵能修(操作节点本身就是 taint 源,不依赖值的信息量),**byVal 和深拷贝仍以"值的标识符"出现**——如果用对象 identity 当标识符,WeakMap 仍断;如果用值内容当标识符,仍碰撞。

### 3.3 §1.3 拦截 sink 不观察 DOM

运行时 taint graph:DOM 写入时拦截 → 查图 → 找祖先 API。这部分**仍符合**——拦截写入点,不事后观察。✅

但**额外问题**:操作级 taint graph 必须在每个 `textContent = X` 处**查图**(`X` 这个值的 taint 链是什么)。如果"值的 taint"以"图遍历"实现,每次 DOM 写入都要反向 BFS——**比 Map lookup 慢几个数量级**。

### 3.4 §11 性能——命中 §11.5 "2-10x 慢" + §11.6 "三选二"

| 成本 | 运行时 taint graph |
|---|---|
| 内存 | **爆炸**:每条赋值/运算/调用 = 一个节点 + 几条边。长会话图无限增长,即便 LRU 仍是大对象(每组件每 prop 一节点)。 |
| 启动 | 立即建图,首次 render 时图已大 |
| 写入拦截 | 反向 BFS 查祖先,O(图深度) |
| 库内部 | **必须插桩**(否则断) → 库变慢 + 库内部类型判断被破坏(`typeof` 同 DESIGN.md §7.3 硬点 A) |
| 大表格 | 库插桩后每 cell 每 prop 每运算都是图边 → §11.6 的"千行表格 2-10x 慢"场景默认发生 |
| prod | 不可开(§11.6 三选二:全插桩 + 便宜 + 常驻只能选两个) |

### 3.5 §14 否决方案——与 Jalangi/NodeProf 同源

DESIGN.md §14 第二条:

> 全量 Jalangi2 taint → 完备但操作级全插桩,开销/维护不可承受;minified 代码脆弱。改为定向 transform(仅三类运算)。

运行时 taint graph(解读 A)**就是 Jalangi 思路**——只是"图"包装更漂亮。**DESIGN.md §14 已经否决**。提议若指 A,等于推翻已否决方案。需重新证明 §14 否决理由不成立(性能、维护、minified 脆弱),但提议文档没给。

### 3.6 第一性原理的总判定

| 原则 | runtime taint graph | 判定 |
|---|---|---|
| §1.1 两端可观测 | 必须插桩中间运算 | ❌ 违反最小爆炸半径 |
| §1.2 identity 传播 | ✅ 沿边 | 半对齐 |
| §1.3 拦截 sink | ✅ | 对齐 |
| §1.4 opt-in 不改写 | ❌ 必须改写库 | 严重违反 |
| §1.5 宁可未知不可错 | ✅ | 对齐 |
| §14 否决 Jalangi | = Jalangi 思路 | ❌ 已被否决 |

## 4. 关键追问:"图"真的消解了按值的根因吗?

不。它**只是把根因的位置换了**。逐项复审:

### 4.1 byVal 碰撞 → 图边能否消解?

**消解不了 byVal 本身**。运行时 taint graph 仍要把 taint 挂到某种标识符上:
- 挂对象 identity(WeakMap)→ 深拷贝断
- 挂值内容 → byVal 碰撞
- 挂图节点 → 必须有"找到图节点的 key",key 仍是值/对象 identity,**根因回到原位**

**唯一例外**:如果图引擎有"操作记录 + 回放"能力,查询时不靠"key 反查",而是从操作日志正向回放("DOM 节点 D 是 opN 的 output,opN 的 input 是 opM,...")。这要重放所有相关操作,代价不可接受。

### 4.2 深拷贝断 → 图边能否消解?

**部分修**。如果 `cloneDeep(x)` 被识别为 Operation 节点 `OpCloneDeep`,边 `OpCloneDeep.input = x` / `OpCloneDeep.output = y`,那 y 沿边可追到 x。**但**:
- 仍要识别 `cloneDeep` 调用(白名单)
- 自定义深拷贝未识别仍断
- `JSON.parse(JSON.stringify(x))` 仍要识别

**与现行 `__passthrough` 白名单 + babel 识别同构**,**没有本质改进**——只是把"复制 SM/fieldMap"换成"建图边"。两边维护成本等价。

### 4.3 低熵失效 → 图边能否消解?

**真修**。这是图引擎**唯一胜过现行**的根因。操作节点本身就是 taint 源,与值的信息量无关。`status = 0` 写入 DOM 时:`textContent = taint(OpStatusField)` —— OpStatusField 的 taint 来自 ApiSource,**绕开值通道**。

但**怎么知道写入的"0"是 OpStatusField 的 output?** —— 必须有某种"值 → 图节点"的映射。**绕回 byVal/对象身份二选一**。

### 4.4 库内墙 → 图引擎能破吗?

**不能**。库内部未插桩 = 库内部不产生 Operation 节点 = 库边界图断。**唯一解仍是 §7.5 档2(结构适配器)**或档3(blessed 库插桩)。**图引擎不解决这个问题,只是把问题换个名字**。

## 5. 如果一定要做"纯图",正确路径是什么?

### 5.1 路径 X:静态图(DESIGN-STATIC.md)

**走 DESIGN-STATIC.md**。理由:
- 真命中三类根因(§4.1 库内墙天然免疫、§4.3 低熵不依赖值、§4.2 深拷贝用 union 处理)
- 零运行时归因
- 静态图本身就是"纯图"——节点 = ApiSource/Component/RenderBlock,边 = produces/derived-from/renders
- **已有文档**(DESIGN-STATIC.md 12 章,15 个 case,5 期落地)

**问题**:不是"运行时引擎",粒度止于"组件 / 列表项 API 级",**不做记录级**(DESIGN-STATIC.md §3.4)。

### 5.2 路径 Y:升级现行按值架构的"边"模型

如果坚持运行时、按值追踪的范式,**升级图存储**(解读 B)是有价值的工程改进:
- 把 `forward = Map<fieldId, Set<edge>>` + `reverse = WeakMap<node, Map<fieldId, edge>>` 升级为通用图
- 查询接口改 BFS / 反向图遍历
- 节点统一类型:Field / Object / DomNode / Operation / Control
- 边统一类型:data / control / conditional / temporal

**价值**:统一数据结构,后续能加新边类型 / 新节点类型更方便。**不解决根因**,但**降低后续扩展成本**。

### 5.3 路径 Z:运行时 taint graph(解读 A)

**不建议**。理由见 §3。与 DESIGN.md §14 否决方案同源。

## 6. 提议到底在解决什么问题?——回到命题诊断

### 6.1 如果是"byVal 碰撞 + 深拷贝断身份"——已经有解

现行 `__passthrough`(`babel-runtime.js:37-66`)+ 白名单(`babel/plugin.js` `DEEP_CLONE_FNS`)已修深拷贝(§1.2)。byVal 碰撞是兜底逻辑的固有取舍——**显式块级降级即可,不需要换架构**。

### 6.2 如果是"低熵失效"——真问题,但不必换架构

`status = 0` 漏检。可用**块级字段位**(`__wdpp_fields`,现行已实现 §3 `stamp-origin.js:208-238`)走"字段级"而不是"值级":即使值是低熵,字段位是确定的。`lookup(node)` 时优先字段级,降级值级。

**这是"按字段"追踪而不是"按值"追踪**——抽象升级正确(从值 → 字段),但**实现上只需小改**,不必换图引擎。

### 6.3 如果是"库内变换墙"——结构性限制,图引擎也破不了

库内部未插桩 = 库内信息不可达。DESIGN.md §7.5 已诚实分级:档1(默认边界未知)/ 档2(结构适配器)/ 档3(blessed 库插桩)/ 档4(库自带)。

**图引擎在这个问题上等价于"操作级全插桩",即档 3 推到极致**。DESIGN.md §7.5 已论证档 3 推组件库"代价显著",即千行表格 2-10x 慢。

### 6.4 提议的真正价值——抽象升级的方向感

提议方向感是对的:**从"按值"升级到"按操作/按字段"**。但:
- 不必换"图引擎"形态
- 现行 `__wdpp_fields`(字段位)+ `SM`(字段槽位)+ `objectIndex`(子树并集)+ `__readProp`(字段读取记账)+ `fiberReads`(字段读取 fiber 维度)**已是"按字段追踪"的雏形**
- **要做的不是重定位,是补完**:把字段位追踪推到所有运算边界,而不是只在深拷贝边界补

## 7. 如果提议坚持要做图引擎——前置条件和最小设计

为避免无脑否决,假设提议坚持,给一个最小可行设计。但要先承认:这等同于 Jalangi2 思路复现,需要证明 §14 否决理由已不成立。

### 7.1 前置条件

| 条件 | 说明 |
|---|---|
| 证明 §14 否决理由不成立 | 性能、维护、minified 脆弱 |
| 提供成本数据 | 全量插桩下千行表格实测 2-10x 慢的应对 |
| 库内部插桩策略 | 不插桩库则图断,这是死结 |
| 类型判断(`typeof`)破坏的对策 | DESIGN.md §7.3 硬点 A |

### 7.2 最小设计

```
节点:
  - ApiSource(url)        // 网络层拦截创建
  - Field(parent, key)     // 字段引用
  - Operation(type, args)  // 运算/调用/赋值
  - DomNode(element)       // DOM 写入拦截创建
  - ControlFrame(if/while) // 控制流 frame

边:
  - produces(parent, child)  // parent 产生 child
  - derived-from(a, b)       // a 派生自 b
  - writes-to(op, dom)       // op 输出写入 dom
  - conditional-by(frame, op)// op 在 frame 内
  - temporal(op1, op2)       // op1 -> op2 时间序

查询:
  lookup(domNode) -> 反向 BFS 收集 ApiSource 集
  queryField(field) -> 正向 BFS 收集 DomNode 集
```

### 7.3 致命问题

| 问题 | 后果 |
|---|---|
| 库内部不插桩 | 库边界图断,与现行一致 |
| 必须全量插桩 | 库变慢,千行表格场景默认发生 |
| 类型判断被破坏 | `typeof (a+b) === 'string'` 拿到 'object' |
| 大对象每字段每运算一节点 | 内存爆炸,GC 卡顿 |
| 反向 BFS 查询每次写入触发 | 写入性能退化到 ms 级 |
| 图无限增长 | 需要 LRU,但语义会断 |

### 7.4 与 §14 否决理由对照

> 全量 Jalangi2 taint → 完备但操作级全插桩,开销/维护不可承受;minified 代码脆弱。

**所有否决理由对运行时 taint graph 全部成立**。提议若指这个,需先证伪 §14。

## 8. 诚实边界——本评议的不确定性

### 8.1 提议解读不唯一

我还原了三种解读,核心评议针对解读 A(运行时 taint graph)。解读 B(改图存储,值仍盖戳)价值低,不在深审范围。解读 C(静态图)已在 DESIGN-STATIC.md 文档化。

**用户原话仅一句**:纯图架构重定位(从按值追踪到血缘图引擎)。**歧义**:
- "图引擎" = runtime engine → 解读 A
- "图引擎" = 通用图存储 → 解读 B
- "纯图" = 静态图(DESIGN-STATIC.md 思路)→ 解读 C

我默认解读 A 是核心提议,因为 B/C 不需要"重定位"(B 是优化,C 已有文档)。

### 8.2 DESIGN-STATIC.md 是否就是提议所指?

有可能。提议者也许在指"把运行时按值追踪换成静态图 + 轻量运行时(fiber 只读)"。如果是,**答案明确:✅ 可行,且 DESIGN-STATIC.md 已是完整方案**。

**判定**:如果提议是"运行时图引擎"——❌ 不可行(见 §3);如果提议是"静态图归因为主,运行时降级"——✅ 可行,沿 DESIGN-STATIC.md 路径走。

### 8.3 现行实现是否已部分"图化"

是的:
- `graph.js` 已是双向图(filedId -> node, node -> fieldId)
- `forward/reverse` 是图的两种遍历方向
- 节点类型隐含存在(fieldId / domNode / control frame)

**现行"按值"的问题不是图存储的问题**,而是 **"值作为反查入口"的问题**。提议要换的不是存储,是**入口**——这个抽象升级可以走路径 X(静态)或路径 Y(升级现行边模型),不必走路径 Z(运行时 taint graph)。

### 9.3 第一性原理的最终判定

DESIGN.md §1 第一性原理 5 条:
- §1.1 两端可观测 → 解读 A 违反最小爆炸半径
- §1.2 追踪 identity 不追踪 value → 解读 A 半对齐(挂载点仍需值)
- §1.3 拦截 sink → 解读 A 对齐
- §1.4 opt-in 不改写 → 解读 A 严重违反(库内插桩)
- §1.5 宁可未知不可错 → 解读 A 对齐

**5 条里 1.5 条对齐,1 条半对齐,2.5 条违反或严重违反**。

按 memory 的"工作铁律:第一性原理/通用/禁 by case":

> 提议方向感对(从按值升级到按字段/按操作),但实现形态错(选运行时 taint graph 而不是静态图 / 字段位补完)。**精确做不到就诚实降级块级并标置信度**——这正是现行 §9 置信度分级在做的工作。

## 10. 我的建议(给提议者)

### 10.1 如果目标是"消除 byVal 碰撞 + 深拷贝断身份"

**不要换架构**。继续完善 `__passthrough` 白名单 + 自定义深拷贝配置 + 库适配器。**这是工程工作,不是架构问题**。

### 10.2 如果目标是"低熵值也要字段级"

**现行已部分支持**:`__wdpp_fields` 字段位含低熵字段。补完策略:
- 优先用 `__wdpp_fields` 字段位追溯,不靠值
- `__readProp`/`__fieldGet` 在字段读取时盖字段位
- DOM sink 优先字段位查,值级作 fallback

**不需换图引擎**。

### 10.3 如果目标是"破库内墙"

**图引擎也破不了**。走 DESIGN.md §7.5 档 2(结构适配器) + 档 3(blessed 库插桩)。这是结构性限制,**不是抽象问题**。

### 10.4 如果确实要"运行时图"

**重新论证 §14 否决理由不成立**——这是提议的硬门槛。如果只停留在"形态升级",**没有充分理由推翻 §14**。

### 10.5 真正的路径

**静态图 + 轻量运行时**(DESIGN-STATIC.md)。这是命题正确的"纯图架构",零运行时归因,库内天然免疫,粒度止于组件/列表项 API——**足够覆盖"哪个 API 影响了屏幕"这个原始问题**。

**与现行运行时按值追踪并存**(粒度分工):静态图答 could + 组件级 API,运行时按值答 did + 字段级 / 记录级。
